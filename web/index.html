Schema Architecture

3NF Compliant Referential Integrity

Third Normal Form (3NF)

Every table is designed to satisfy 1NF, 2NF, and 3NF — eliminating all transitive dependencies. No data is duplicated across tables; departments, users, and categories are each stored once and referenced by foreign keys.

Cascading Referential Integrity

All child entities (PolicyVersions, ChangeHistory, Approvals) reference the parent Policies table via foreign key constraints. Query 2 demonstrates a manual cascade delete that removes all dependent rows across 3 child tables before deleting the archived policy — preserving data integrity.

Relationship Summary

  • 1:N Department → Users, Policies
  • 1:N Category → Policies
  • 1:N Policy → Versions, History, Approvals
  • 1:N User → Policies, Versions, History, Approvals
